In the exact pinned Tilt source (`753c01455`), down delegates each Compose project to [`docker compose down --remove-orphans`](https://raw.githubusercontent.com/tilt-dev/tilt/753c01455/internal/dockercompose/client.go), selected through the project arguments from [`internal/cli/down.go`](https://raw.githubusercontent.com/tilt-dev/tilt/753c01455/internal/cli/down.go), rather than to Silo's verified IDs.

   A concrete interleaving is: Silo removes receipted Redis parent P and its anonymous volume at line 47; a wrapper pauses the subsequent `tilt down`; another trusted agent accidentally recreates the service with Compose under the same project, producing replacement container Q and a new image-declared anonymous volume W; the wrapper resumes Tilt. Compose down selects Q by its project/service identity and removes Q and the project network. It does not need P's old ID and does not verify Silo's receipt. This is deletion of the replacement object, violating the stated threat boundary.

   Default Compose down preserves anonymous volumes rather than taking `--volumes` ([Compose down contract](https://docs.docker.com/reference/cli/docker/compose/down/)). Thus W can survive, but it is Q's unreceipted child, not P's recorded child. `anonymousLeaks` only examines historical receipted mounts (`src/backends/ownership.ts:243-245`), and a Redis image-created random volume name need not match the claimed project volume prefix. Once Compose has removed Q and the network, post-down capture cannot observe Q, so `down --clean` can retire with W unreported and claims released. The defect is therefore both peer-container deletion and loss of the promised leak/claim protection; it is not merely a theoretical extra Docker call.

   The new paused-delete regression cannot detect this path because its barrier only intercepts `docker volume rm` (`scripts/allocation-rehearsal.ts:519-545`). Add a regression that pauses the real `tilt down` after the receipted parent is gone, creates the replacement through real Compose, resumes teardown, and requires Q/W and claims to remain intact. A second name inspection immediately before Tilt would leave the same check/act race. The Compose portion of delegated teardown must not retain project/name-wide deletion authority after Silo's exact-ID cleanup; non-Compose Tilt teardown needs a construction that does not reintroduce that authority. This finding is a demonstrated source/upstream-code path, not a race I executed against Docker in this read-only review.
